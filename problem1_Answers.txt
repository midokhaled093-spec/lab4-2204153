-- Q1.3 DELETE (b, continued) the correct order, inside a transaction
-- The removal is wrapped in START TRANSACTION ... ROLLBACK so the data stays intact for the next queries.
------------------------------------------------------------------------------
SQL and output (each statement is echoed between dashed lines, then its result):
--------------
START TRANSACTION
--------------

--------------
UPDATE department SET mgr_ssn = NULL, mgr_start_date = NULL WHERE Dnumber = 3
--------------

--------------
DELETE FROM works_on  WHERE essn IN ('666666666','777777777') OR Pno IN (SELECT Pnumber FROM project WHERE Dno = 3)
--------------

--------------
DELETE FROM dependent WHERE essn IN ('666666666','777777777')
--------------

--------------
DELETE FROM project   WHERE Dno = 3
--------------

--------------
DELETE FROM employee  WHERE ssn = '777777777'
--------------

--------------
DELETE FROM employee  WHERE ssn = '666666666'
--------------

--------------
DELETE FROM department WHERE Dnumber = 3
--------------

--------------
SELECT * FROM department
--------------

+---------+-------------+-----------+----------------+
| Dnumber | Dname       | mgr_ssn   | mgr_start_date |
+---------+-------------+-----------+----------------+
|       1 | Engineering | 111111111 | 2015-01-01     |
|       2 | Research    | 444444444 | 2018-09-01     |
|       4 | Marketing   | NULL      | NULL           |
+---------+-------------+-----------+----------------+
--------------
ROLLBACK
--------------

--------------
SELECT * FROM department
--------------

+---------+----------------+-----------+----------------+
| Dnumber | Dname          | mgr_ssn   | mgr_start_date |
+---------+----------------+-----------+----------------+
|       1 | Engineering    | 111111111 | 2015-01-01     |
|       2 | Research       | 444444444 | 2018-09-01     |
|       3 | Administration | 666666666 | 2012-03-15     |
|       4 | Marketing      | NULL      | NULL           |
+---------+----------------+-----------+----------------+

ANSWER: Order: (1) clear the manager of the department (department.mgr_ssn points to an employee); (2) delete the works_on rows and dependents of its employees, and the works_on rows of its projects; (3) delete its projects; (4) delete its employees, the supervised one (777777777) before his supervisor (666666666); (5) delete the department itself. Children first, parent last. ROLLBACK then undid everything, so department 3 is back.

-- Q1.7 (b) same, counting only employees with salary above 3000
------------------------------------------------------------------------------
SQL and output (each statement is echoed between dashed lines, then its result):
--------------
SELECT Dno, COUNT(*) AS employees
FROM employee
WHERE salary > 3000
GROUP BY Dno
HAVING COUNT(*) > 2
--------------

+-----+-----------+
| Dno | employees |
+-----+-----------+
|   1 |         5 |
+-----+-----------+

ANSWER: WHERE filters single rows before the grouping and cannot use aggregate functions, while HAVING filters whole groups after the grouping and can use COUNT, SUM, AVG, and so on.

-- Q1.10 (a) every department with its number of employees (including 0)
------------------------------------------------------------------------------
SQL and output (each statement is echoed between dashed lines, then its result):
--------------
SELECT d.Dnumber, d.Dname, COUNT(e.ssn) AS employees
FROM department d LEFT JOIN employee e ON e.Dno = d.Dnumber
GROUP BY d.Dnumber, d.Dname
ORDER BY d.Dnumber
--------------

+---------+----------------+-----------+
| Dnumber | Dname          | employees |
+---------+----------------+-----------+
|       1 | Engineering    |         5 |
|       2 | Research       |         3 |
|       3 | Administration |         2 |
|       4 | Marketing      |         0 |
+---------+----------------+-----------+

ANSWER: COUNT(e.ssn) counts only the non-NULL values, so a department with no employee gets 0. COUNT(*) would give 1 for it, because the LEFT JOIN keeps one row with NULLs.

-- Q1.11 self join: employee with the name of his or her supervisor
------------------------------------------------------------------------------
SQL and output (each statement is echoed between dashed lines, then its result):
--------------
SELECT CONCAT(e.fname, ' ', e.lname) AS employee, CONCAT(s.fname, ' ', s.lname) AS supervisor
FROM employee e LEFT JOIN employee s ON e.super_ssn = s.ssn
ORDER BY e.lname
--------------

+---------------+--------------+
| employee      | supervisor   |
+---------------+--------------+
| Nour Adel     | Sara Mostafa |
| Laila Essam   | Ahmed Hassan |
| Omar Fathy    | Ahmed Hassan |
| Ahmed Hassan  | NULL         |
| Mona Ibrahim  | NULL         |

| Hossam Nabil  | Ahmed Hassan |
| Hany Salah    | Nour Adel    |
| Youssef Samir | Sara Mostafa |
| Karim Tarek   | Mona Ibrahim |
+---------------+--------------+

ANSWER: LEFT JOIN is used so that the employees without a supervisor are still listed (supervisor = NULL). With a plain JOIN they would disappear.
